    MethodGeneralization
    Methodology

    Expect · Breach · Survive. A discovery engine, not a report generator.

    Candidates come from accounting-identity driver trees and the management claim ledger — never from mining arbitrary correlations. Each candidate must pass fixed gates and a falsification battery before it can be reported.

    Deterministic code vs language model

    the LLM never types a number

    Code decides

    • XBRL parsing, table extraction checks, arithmetic reconciliation
    • Driver decomposition and peer residualisation
    • Robust surprise, persistence and specification curves
    • Falsification tests, gates, scoring and strength rule
    • Every rendered number (reference to a computed node)

    Language model reads & writes

    • Turns transcripts and notes into typed, cited claims
    • Proposes mechanisms + computable corollaries for top candidates
    • Plans bounded counter-evidence searches
    • Writes prose bound to evidence IDs — digit-free

    Discovery score

    one weak dimension sinks a candidate
    Gates: reconciled · ≥2 families · ≥2Q persistence · no accounting artefact
    Score = GMw( surprise, specificity, persistence,
            materiality, corroboration, survival )
          × narrative-gap × novelty
    Weighted geometric mean · robust z-scores are ranking heuristics, not p-values · the full funnel is published with every run.
    MethodGeneralization
    Generalization

    Defined at archetype level — not company level. No company-specific tuning.

    Indian banks, NBFCs and insurers report in regulator-prescribed formats, so the driver trees are archetype-level by construction. An archetype router reads the reporting taxonomy; any listed company in the sector — including outside the NIFTY 50 — runs through the same code.
